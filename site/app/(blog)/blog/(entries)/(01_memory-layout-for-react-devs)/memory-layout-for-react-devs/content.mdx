In React, you manipulate values: objects, arrays, props, state. You care about
their identity and shape, but rarely their physical location. Underneath, every
value is represented by bytes in memory. Systems languages expose more of
those details.

In Rust, the type gives us another useful fact. `[u16; 4]` tells us there are
four elements and every element consumes two bytes. The payload is eight
consecutive bytes. No detective work required.

  describes how its data can exist in memory.

>
  Contiguous means close
</ArticleHeading>

An array's elements sit next to each other. If the first byte starts at address
`0x1000`, the next byte is at `0x1001`. This makes the addresses predictable
when iterating through the array.

<MemoryInspector />

The processor benefits because fetching one location often brings nearby data
into cache. Walking a compact array is like reading books arranged on one shelf.
Chasing pointers is more like following a scavenger hunt across the library.

  Alignment: the invisible grid
</ArticleHeading>

Many values prefer addresses divisible by a particular number. A `u32`, for
example, typically wants a four-byte boundary. When fields do not line up, the
compiler may insert unused bytes called **padding**.

This is not waste caused by a lazy compiler. Alignment lets the machine read
values efficiently and, on some architectures, safely. Rearranging fields can
sometimes reduce padding. Doing so blindly can make an API worse to save a
handful of bytes.

These layout details matter when JavaScript exchanges data with a lower layer:

- **Typed arrays** make element size and contiguous storage explicit.
- **GPU buffers** demand exact layouts because shaders cannot guess what your
  objects meant.
- **Serialization** encodes values in a byte format another system can read.

React handles UI composition. Rust gives you more control over memory layout.
Understanding that layout helps when you pass data between JavaScript and
systems code.
